# 0002 · 备份三条路由只允许 admin

- **状态**：已采纳
- **日期**：2026-10-07

## 背景

`POST /api/backup/{export,verify,restore}` 三条路由原先用的是 `AuthUser`
extractor —— 只要登录就能调。

而备份的**源是整个数据根**（`<实例根>/data` 及其同级 `backups`），那里装着
**所有**用户的会话与消息。在多用户部署下，任何一个登录用户都能把别人的对话
全文导成文件。`verify` 还会逐个重算全量文件的 sha256，并把「哪些文件不在了」
这条目录级信息回给调用方；`restore` 虽不在进程内写盘，却会回显服务端绝对路径
与一条可直接照抄的 `quill restore` 命令。

M5（多用户）尚未开始，所以这条越权当时**实际不可利用** —— 但 M1 已经是 MVP，
接口现在就摆在那里。

## 决定

三条一律改用 `RequireAdmin`，与 `/api/admin/config` 同一把尺：它们都是
「实例级」操作。

## 被否决的方案

| 方案 | 为什么否决 |
|---|---|
| 保持登录即可，等 M5 再收紧 | 「等有洞了再堵」是错的顺序。接口一旦发布就可能被外部调用；而且 M1 已达成，仓库是公开的 |
| 只给 export 加 admin，verify/restore 保持开放 | verify 读的是**同一份**数据，restore 回显的是**同一套**路径。只堵一条等于没堵 |
| 新建一个「backup 管理员」角色 | 一个只有三个端点用得上的角色不值得维护；而且 Owner 已经存在，够用 |

## 后果

**变好了**：横向越权消失。

**变糟的**：非 admin 用户点备份页会拿到 403。**界面有没有把这句话说明白，
必须用浏览器实际点一遍才算数** —— 这条已写进 `BACKLOG.md` 的 B4-1「待复验」
与 `MILESTONES.md` 的 M1 剩余项。不要因为测试过了就当它过了。

## 证据

测试 `a_logged_in_non_admin_cannot_reach_any_backup_route`：用**真的**非 admin
令牌去打，且先造一份真实存在的备份，确保 403 来自鉴权而不是「目录不存在」。
第一版这个测试写成拿另一个不存在的令牌去打，得到 401 而红 —— 说明必须用
注册的令牌，否则测的不是这条边界。
