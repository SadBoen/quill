# 0005 · 缺上游参考源码时门禁报「未跑」而非失败

- **状态**：已采纳
- **日期**：2026-10-07

## 背景

四道门禁依赖只读参考源码 `.octop-ref/octop`（octop 的 pin 记在 `UPSTREAM.md`，
仓库地址由 `OCTOP_REPO` 提供，**不在公开仓库里**）：

| 门禁 | 依赖它做什么 |
|---|---|
| `.library-check.mjs` | 专家库「源 vs 产物」双向比对 |
| `.upstream-check.mjs` | 比对 `UPSTREAM.md` 记的 pin 与本机实际检出 |
| `.provenance-check.mjs` | 把 `UPSTREAM-USAGE.md` 里每条上游引用逐行打开核 |

`.octop-ref/` 按 `.gitignore` 不入库，所以 **fresh clone 上必然没有**。
原先这三道走通用的 `run_text_gate`，于是缺上游时一律判「门禁没过」。

## 决定

分成两种情况，**不许混**：

- **没有上游** → 记「未跑」，不判失败。
- **有上游却判不过** → 才是失败。

最后统一以「**不算全绿**」退出码 1 收尾，并把缺什么逐条列出来
（原先只说「缺 node」，而少跑的原因可能不止一个）。

## 被否决的方案

| 方案 | 为什么否决 |
|---|---|
| 缺上游时判通过 | 最坏的一种：退出 0 就是骗人。「没跑」和「跑过且通过」是两件完全不同的事 |
| 缺上游时判失败（现状） | 指向错误的修复方向 —— 让人去修一份根本没坏的代码 |
| 把 `.octop-ref` 提交进仓库 | octop 有 250MB，且是别人的私有代码 |
| 在 CI 里干脆不跑这三道，也不说 | 那等于把「出处可复查」这个卖点悄悄扔了，还不留痕迹 |

## 后果

**变好了**：两种「不绿」被区分开了 —— 「门禁没过」指向修代码，
「未跑」指向补环境。

**欠下的**：CI 里这三道被拆成独立的 `gates-upstream` job，只在仓库配了
`OCTOP_REPO` secret 时才跑，没配就显示 **skipped 而不是通过**。
GitHub 无法给 fork 的 PR 注入 secret，所以本地开发者能跑的检查，
外部贡献者跑不到 —— 这个缺口要如实说出来，不能装作没有。

## 证据

实测：把 `.octop-ref/octop` 临时改名后，三道如实报「未跑」、退出码 1、
并写明取回命令；改回来后恢复全绿。
