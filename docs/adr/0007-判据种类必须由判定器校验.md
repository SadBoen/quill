# 0007 · 判据种类必须由 selfCheck 校验，且与判定器共用一份

- **状态**：已采纳
- **日期**：2026-10-08

## 背景

以代码为准复核时发现：`project/items.mjs` 里 **B6-4** 写的是 `kind: 'script'`、
**B6-6** 写的是 `kind: 'auto'`，而 `scripts/status.mjs` 的 `decide()` 只认
`test / cmd / absent / manual` 四种 —— 这两条被判成 **「判据本身坏了」**（真实状态未知）。

更要命的是第二半：`selfCheck()` 里**没有「未知 kind」这一支**，
所以 `node scripts/status.mjs --self-check`（`gates.sh` 里跑的那道）报「全部成立」。
一道专门用来抓「判据声明坏了」的自检，**抓不到这一类**。

这与仓库反复吃过的亏同属一类：不是判定错了，是**检查压根没覆盖那一支**，
而且静默通过。

## 决定

1. 把合法种类抽成 `KNOWN_KINDS`，`decide()` 与 `selfCheck()` **共用同一份**——
   加一种 kind 只改一处，两边不可能再漂移。
2. `selfCheck()` 遇到未知 kind 立即报错，并列出合法值。
3. `status-selftest.mjs` 增加**场景 13**：喂 `kind:'script'` / `kind:'auto'` 进 `selfCheck`，
   断言它们被报出来；并加一条反向断言（合法 kind 不误报）。
4. 顺手修两条坏的声明：B6-4 改 `cmd`（跑 `node .octop-baseline-check.mjs`）、
   B6-6 改 `cmd`（跑 mbti 两组测试，标 `slow`）。
5. 另修一条**方向写反**的判据：B2-2「成员执行器存在」原先绑
   `{ kind: 'absent', path: '…/member_executor.rs' }` —— 文件**不存在**时判「已验证」，
   即一个说「存在」的条目靠「不存在」通过。改成 grep 具体结构（当前如实报「未通过」）。

## 被否决的方案

| 方案 | 为什么否决 |
|---|---|
| 给 `decide()` 加 `script` / `auto` 两种新 kind | 会再开一份「哪种 kind 算数」的清单，正是漂移的来源。而且这两条的实质就是「跑条命令」，`cmd` 已经能表达 |
| 只修 `items.mjs` 里那两条，不动 `selfCheck()` | 洞还在：下一个人再写一个未知 kind，自检照样报绿。**修数据不修机制，等于等着复发** |
| 在 `selfCheck()` 里只 `console.warn` 不报错 | 自检的退出码是门禁的一部分。warn 不进退出码，等于没接线 |

## 后果

**变好了**：`status` 自测从 26 项涨到 29 项；「判据本身坏了」从 2 条降为 **0 条**；
B2-2 从「假通过」变成如实报「未通过」——一个真实缺口被暴露出来，而不是被一个反向判据掩住。

**欠下的**：`selfCheck()` 现在对「未知 kind」只列合法值，不告诉你该换成哪个；
换 kind 需要人判断它的实质（跑命令还是绑测试），这一步没法自动化，也不该自动化。

**已用变异验证**：把 `KNOWN_KINDS` 那一支删掉，场景 13 立刻变红。
