# 0003 · 派工校验团队存在，但不按 team_id 过滤

- **状态**：已采纳
- **日期**：2026-10-07

## 背景

`/api/teams/{id}/dispatch` 的两条路由都写着 `Path(_team)` —— 下划线前缀，
**team id 直接丢弃**。于是：

- `POST`：编一个不存在的团队 id 也能拿到 200，台账里多出一条指向虚空的派工。
- `GET`：问一个编出来的团队 id 会拿到 200 + 空记录，读起来像
  「这个团队没有派工历史」。

后者尤其恶劣：**把「没有这个东西」说成「它没有记录」**。

台账（`dispatches`）的键是 `(owner, room_id, round)`，**不是 team_id**。

## 决定

分两步，本次只做第一步：

1. **两条都先按 `(user_id, id)` 校验团队存在**，不存在或已软删一律 404。
   GET 额外回显 `team_id` 并加 `filtered_by: "room_id+round"`，如实说明
   自己按什么过滤。
2. （未做）要让列表真的按团队过滤，需要把 `team_id` 并进台账键。

`teams` 的主键就是 `(user_id, id)`，所以校验一律带 `user_id` —— 只按 id 查
等于把别人的团队算成自己的。

## 被否决的方案

| 方案 | 为什么否决 |
|---|---|
| 只按 team_id 过滤，不校验存在性 | 编一个 id 拿到的仍是空记录，歧义照旧 |
| 把 `{id}` 从路由里去掉 | URL 自解释性没了，且是破坏性变更 |
| **顺手把台账键改成含 team_id** | 改键会改写已有数据。按 ADR-0001，产品契约变更先问。见后果一节 |

## 后果

**变好了**：不存在的东西不再被说成「它没有记录」。两条路由同一把尺。

**欠下的**：GET 仍然**不按团队过滤** —— 校验存在性与「返回的记录属于这个团队」
是两件事。响应里的 `filtered_by` 就是在说清这个区别，别把它当装饰删掉。

**顺带暴露的**：改完之后 404 有了两种含义（路由没挂上 vs 资源不存在），
而 `http_contract.rs` 里那条「路由必须已注册」的断言只看状态码，于是变红。
它改成认错误信封里的 `code`（`not_found` vs `entity_not_found`）。
这与 B1-2 是同一件事：**未注册、查无此人、未接通，三种状态必须分得开**。
已变异验证：把路由从 `build_router` 摘掉，契约测试确实变红。

## 证据

- `dispatch_to_a_team_that_does_not_exist_is_404_and_writes_nothing`
- `listing_dispatch_of_a_missing_team_is_404_not_an_empty_200`
