# 0004 · 事实由命令生成，不许手写进文档

- **状态**：已采纳
- **日期**：2026-10-07

## 背景

`MILESTONES.md` 记着「代码门禁全绿（Rust 280/1，前端 184/20）」、
「`npm run lint` 跑不起来，缺 `eslint.config.*`，加它属于改依赖政策，要你点头」。
2026-10-07 实测：**1175/0 与 241/0**，eslint 配置早已入库，且依赖本来就在，
缺的只是那份文件，不需要改依赖政策。

同一天实测的还有：`gates.sh` **压根不跑 lint**，所以「门禁退出 0」与
「eslint 报 2 个 error」可以同时成立而没人发现。

根因不是人不勤快，是**事实被抄进了需要人维护的散文里**。散文一改数字就错；
数字一错，整份文档的可信度一起塌。`BACKLOG.md` 自己的开头就写着
「本文件以前就是重灾区」—— 它早就知道，只是没找到病根。

## 决定

**判据（人的判断，稳定）留在文档；事实（测量结果，易变）必须由命令当场跑出来。**

具体落地：

1. 每条待办在 `project/items.mjs` 里声明「怎么算做完」（`verify`）。
2. `scripts/status.mjs` 当场跑这些判据，输出状态。**人不打状态标记。**
3. `scripts/status-selftest.mjs` 证明判定逻辑真的会红。
4. `MILESTONES.md` / `BACKLOG.md` 里**不许再出现任何测试数字或状态标记**。

「需人工」的判据必须**显眼地单列**，不许混进「已通过」—— 藏起来的未验证
比明摆着危险得多。

## 被否决的方案

| 方案 | 为什么否决 |
|---|---|
| 继续手工维护数字，只是记得勤快点 | 这就是现在的做法，实测已经烂了。靠自觉的东西不该被当作判据 |
| 引入外部 PM 工具（Jira/Linear 等） | 那些工具自己的状态也会烂，而且多一个外部依赖。病根是「人维护状态」，不是「工具不够好」 |
| 引入完整框架（scrum / SAFe 等） | 对单人项目开销巨大，而且它**制造**更多要人维护的散文状态 —— 即第 4 种病 |
| 全部自动化，连「需人工」也想办法自动化 | 有些判据就是只能人工（浏览器实点）。硬造一个假自动化，比明说「这条没验」更坏 |

## 借鉴（不是原创）

核心模式来自 **GitOps**（状态声明式地写在 git 里，由控制器对账，漂移自动发现；
Terraform / Kubernetes / Argo CD 都是它）与 **dbt**（声明模型 + 测试，跑一遍
产出「哪些该过哪些没过」）。把它们从基础设施/数据工程搬到**项目管理文档**上，
这个迁移本身是本项目的判断。

判据与事实必须分开，来自 **Diátaxis**（Daniele Procida）关于文档四象限
「混着写有害」的论点。「测试必须有牙齿」来自**变异测试**（mutation testing，
工具：PIT / Stryker / cargo-mut）。

## 后果

**变好了**：文档不再腐烂，因为里面没有会腐烂的东西。

**欠下的**：

- `status.mjs` 全量跑要几分钟（它自己跑 cargo test 与 vitest）。为此分
  `--quick`（只跑便宜的判据，test 类标为「未复查」），门禁里只跑 quick。
- 「需人工」是**公开的缺口**，不是通过。当前仍有十余条，见 `status.mjs` 输出。
- 变异测试目前是**手工做的、一次性的**（改坏 → 看红 → 改回）。工具化要加依赖，
  按 ADR-0001 需先问；且变异测试跑起来慢、存活变异体要逐个判断，
  本身是需要人力的活。等待办多到手工扛不住再上。

## 上线当天就被自己逮到的一个 bug（值得单独记）

第一版 `status.mjs` 解析 vitest 的**默认输出**，找 `✓ ` 开头的行来认定「通过」。

结果：三条绑在前端测试上的判据全部报「存在但没通过」—— 而那三个测试当时
**是真绿的**。

真正的原因不是 ANSI 颜色码，是更根本的一件事：

> **vitest 的默认 reporter 只在失败时打印逐条用例名。全绿时整份输出只有
> 9 行汇总，一个 `✓` 都没有。**

一个「全绿时什么都不说」的输出格式，**没法用来证明「某条确实绿了」**。
按它解析，等于把「没提到」当成「没通过」。

改用 `--reporter=json --outputFile=…`：`assertionResults[]` 里每条都有
`title` / `ancestorTitles` / `status`，一次运行同时给出「有哪些」与「哪些过了」。

这件事本身印证了本文档的前提：**判定逻辑是会错的，而且错的方式很安静。**
所以 `status-selftest.mjs` 不是加分项，是它能不能存在的条件。
