# 0008 · 管理文档以代码为准重建

- **状态**：已采纳
- **日期**：2026-10-08

## 背景

用户明确要求：**"所有管理文档里面的内容都不可信"**，
只有最高指示（Rust 实现 + octop 为壳 + goose 为核）是真实的，
**只看代码实际写了什么**，并**全部重建管理文档**。

以代码为准复核，确认这不是多疑 —— 文档里已经有多处与代码对不上：

- `capabilityGaps.ts` 的实际内容**已经纠正**了「PATCH 未登记」那条，
  而 `BACKLOG.md` 还写着「它现在还写着『未登记』—— 已经错了，要改」。
  即：**清单本身过期了，却以「已核实」的语气写着**。
- `MILESTONES.md` / `BACKLOG.md` 里混着大量上一批人的自我叙述与状态快照。

## 决定

1. **新增 `docs/CODE-TRUTH.md` 作为唯一的事实总账。** 每条事实后面都带**复现命令**；
   对不上就以跑出来的为准，改这份文件。
2. **重写** `README.md` / `MILESTONES.md` / `BACKLOG.md` / `WORKING.md` / `UPSTREAM.md` /
   `REQUIREMENTS.md`：只留「要造什么 / 为什么 / 规程」，**删掉一切不经验证的断言**，
   会过期的事实交给 `CODE-TRUTH.md` 与 `node scripts/status.mjs`。
3. **保留 `project/items.mjs` + `status.mjs` 这套机器判定机制**（见 ADR-0004），
   它是「不撒谎」的落点，重建文档时不动它，只修它的洞（ADR-0007）。
4. 迁移功能清单另立 `docs/OCTOP-MIGRATION-INVENTORY.md`（470 条端点，机器生成）。

## 被否决的方案

| 方案 | 为什么否决 |
|---|---|
| 逐句给旧文档纠错 | 逐句纠错的量比重建还大，而且纠完它仍是一份「需要人维护、必然再腐烂」的散文。病根是文档承载了**会过期的事实**，不是某几句写错了 |
| 直接删掉所有旧文档 | 里面有一部分是**判据**（人写的判断），那部分稳定、有价值（如「为什么 M1 不含注册」）。重建是「分开判据与事实」，不是「全删」 |
| 保留旧文档并加一句「本文可能过期」 | 免责声明会**反向授权**——本项目 B6-4 记过一次真实事故：四条免责声明合起来的效果，是没人再问「它凭什么在这儿」 |
| 把事实也写进 `CODE-TRUTH.md` 并手工维护 | 那就造了第二份会腐烂的散文。所以 `CODE-TRUTH.md` 里的事实**一律带复现命令**，随时可判真伪 |

## 后果

**变好了**：任何一条事实都能当场复核；文档不再声称「已验证」而实际没验。

**欠下的**：

- `UPSTREAM-USAGE.md` 尚未重写。它经 `node .provenance-check.mjs` 逐行核过
  （162 条引用无坏引用），但**门禁只能证文件:line 存在，证不了「已接入」这句判断为真**。
  逐条复核是后续工作。
- `TESTSETS/STATUS.md`（537 行）与 `TESTSETS/ISSUES.md`（2508 行）未重写。
- 迁移清单里的「quill 现状」是按**路由存在性 + 模块有无**判的，
  粒度到「能力域」不到「行为正确性」——它回答「有没有」，不回答「对不对」。
