# ADR-0006 自测必须用被测函数的真实输出，不能手写合成数据

- **状态**：已采纳
- **日期**：2026-10-08

## 背景

`scripts/status.mjs` 是用来算「哪些待办真的完成了」的。它有个自测
`status-selftest.mjs`，26 项断言，用来证明它的判定逻辑不是瞎判的。

2026-10-08 第一次跑全量时，三条前端判据（B1-7 / B1-8 / B3-1a）被报成
**「判据本身坏了」** —— 也就是「判据绑的测试名不存在」。

查下来是 `collectFrontendTests()` 拼用例全名时只取了文件名，
生成 `ChatPage.test.tsx > 用例名`，而 `project/items.mjs` 里写的是
`src/chat/ChatPage.test.tsx > 用例名`。两边对不上。

而这三个测试当时是**真绿的**，`vitest` 报 241 passed / 0 failed。

问题在于：**自测 26 项全绿，却没发现这段是坏的。**

## 决定

**自测里出现的、被测系统产生的字符串，必须由被测函数当场生成，
不许在测试里手写。**

具体到这次：把拼名字那段抽成纯函数 `feFullName()` 导出，
自测改成调用它、并断言输出的**具体字符串**；然后把它的真实输出
原样当作判据名喂给 `decide()`，闭环。

## 被否决的方案

**否决：把自测里手写的 `'fe > 用例甲'` 改成 `'src/chat/ChatPage.test.tsx > 用例甲'` 就完事。**

这看起来是同一个修复，实际上只是把 bug 从代码挪到了测试里。
判据名是手写的合成数据，就意味着**拼名字那段代码改了，自测不会红** ——
而拼名字那段恰恰就是最容易写错、且错了最不容易被肉眼发现的地方
（错的不是判断，是喂给判断的原料）。

**否决：干脆不测拼名字，接受「判据坏了」这个信号。**

不行。信号本身没错，但它报的是「你绑错了名字」，
真实情况是「名字生成逻辑坏了」—— 前者的修法是改一行 YAML 式的声明，
后者的修法是改代码。前者会把真故障当成配置笔误处理掉。

**否决：改 `items.mjs` 里的判据名，去迁就 basename 的输出。**

那等于让声明服从实现。判据名是人读的、要在报告里展示的
（`node scripts/status.mjs` 会原样打印「✓ B1-7 流式输出（SSE）接通」），
仓库相对路径才是人能读懂的形式。

## 后果

变好了：

- 同类故障不会再无声发生：现在只要有人动 `feFullName()`，自测立刻红。
- 这条纪律可以套用到任何「拼字符串喂给判定」的代码，
  判据是：**测试里有没有一个字是手写编出来的？**

变糟 / 欠下：

- 自测从 21 项涨到 26 项，多花几秒。
- `feFullName()` 必须保持纯函数（不碰文件、不跑命令）才能被这样测试。
  这是个约束，但本来也该如此。
- 变异验证目前还是手工做的（把代码改坏、看红、改回）。
  工具化需要新依赖，按 `WORKING.md` 得先问，尚未做。
